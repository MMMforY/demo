# 四个模块

四模块入口由 App 集中维护。模块共享 ID 和数据对象，业务页面各自独立；当前所有数据只读，没有业务状态变化。

## 人群 · Features/Audience

- 目标：理解并维护宏观人群特征，不展示客户名单或个人资料。
- 当前：`AudienceHomeView` 显示两个人群、覆盖人数和三个核心评分；点击进入 `AudienceDetailView`，查看五项评分、主要品类、关联方案及占位说明。
- 输入：`MockDataStore.audiences`、`Audience`、`AudienceScore`、`CategoryPreference`；关联方案反向查询 store。
- 当前输出：导航进入详情／返回，无数据修改。
- 后续页面：列表筛选与画像展开、完整详情、规则编辑、自定义字段、识别状态、历史版本、AI 建议。
- 后续状态：保存规则或采纳建议后生成版本；画像依据不足与低分必须区分。
- 边界：不编辑方案或审批分配，不模拟客户级识别算法；共享对象使用 Shared。

## 方案 · Features/Plan

- 目标：维护具有明确目的和适用客户的营销内容。
- 当前：`PlanHomeView` 每条只有编号、目的、适用客户；点击 `PlanDetailView` 查看固定话术、资源说明、关联人群、来源和版本。
- 输入：`MarketingPlan`、`PlanPurpose`、`CustomerStage` 与统一 store 的人群查询。
- 当前输出：导航，无新增、编辑或资源选择状态。
- 后续页面：编号搜索、目的／客户筛选、创建编辑、店铺资源选择、历史版本、生日和回访规则、AI 建议。
- 后续状态：保存或采纳生成新版本；关联人群多对多。
- 边界：店铺资源只选择既有资源，不创建商品／券／抽奖；不决定最终发送范围。当前只有资源摘要字符串，后续确需选择器再补共享资源模型。

## 发送审批 · Features/Approval

- 目标：核对本次发给谁、用哪个方案、分配多少，确保人工确认。
- 当前：`ApprovalHomeView` 显示一条待审批任务，点击 `ApprovalDetailView` 查看核心评分、版本及 30%／70% 的只读分配，预计 600／1,400 人。
- 输入：`ApprovalTask`、`ABAllocation`、`ApprovalStatus`、`DeliveryStatus` 与人群／方案的共享 ID。
- 当前输出：导航，无审批、比例调整、发送或重试动作。
- 后续页面：待审批／已发送切换、任务调整、人群／方案选择、比例调整、确认、稍后、拒绝、处理记录、结果和失败重试。
- 后续状态：待审批／稍后处理 → 已确认或已拒绝；已确认才可进入执行状态。模拟发送需清楚标注，并与统计 fixture 解耦或明确关联。
- 边界：最多两个方案，每个客户只收其中一个；调整仅作用于任务，不直接编辑人群规则、方案话术或资源。确认后版本与安排冻结，当前尚未实现快照内容和处理记录。

## 数据 · Features/Analytics

- 目标：相同时间和口径下查看汇总及方案效果。
- 当前：`AnalyticsHomeView` 展示 2026/10/05—10/11 固定筛选摘要与五项指标；点击 `AnalyticsDetailView` 查看两方案各自指标和口径说明，没有趋势图。
- 输入：`AnalyticsSummary`、`PlanPerformance`、`MarketingMetrics`；历史任务 ID 和方案版本。
- 当前输出：导航，无筛选或统计计算任务；转化率由计数计算展示。
- 后续页面：近 7 日／30 日／3 个月、人群／方案筛选、指标切换、趋势、同组与跨任务对比、指标明细和空状态。
- 后续状态：模块内筛选选择及展示结果；新增趋势数据需要集中补 fixture。
- 边界：不发起真实统计；合计客户数来自经过去重的摘要，不自动累加跨任务数据；转化率分母为 0 显示“—”。不要改写发送时方案版本或把未知数据当作 0。

## 共享关系

人群与方案通过 `MarketingPlan.audienceIDs` 关联；审批引用人群 ID、版本和一到两个方案 ID、版本；统计关联历史已发送任务及方案版本。其他模块展示编号可查 Shared store，但不能直接调用对方页面。跨 Tab 的跳转如果以后确有演示需求，再由 App 整合者维护共享导航约定。
