# 开发者 D · 数据模块完整开发任务

> 分支建议：`feature/analytics`。
> 主目录：`TouchMarketingDemo/Features/Analytics`。
> 你负责时间／人群／方案筛选、统计摘要、双方案趋势和比较、指标明细、数据状态及模拟批次关联。

## 你的交付目标

将当前固定摘要与详情升级为可筛选、可切换指标、可比较、可追溯任务／版本的本地数据模块。用户能够在同一时间范围比较方案01／02，并区分历史完整样本、新发送统计中、已统计零结果和没有数据。

所有统计来自确定的 Shared fixture 和 C 提供的模拟发送结果，不发起真实查询，不推断客户数据，不执行真实归因算法。完成所有下列必交付页面；不以截图／静态标签变更代替筛选结果变化。

## 1. 基线和文件边界

已有 `AnalyticsHomeView.swift`、`AnalyticsDetailView.swift`；固定区间2026/10/05—10/11，人群01、方案01／02。`AnalyticsSummary` 引用历史 `task-history-01`，不是待审批 `task-01`。`MarketingMetrics` 已保存触达／成交／订单和金额分，转化率为计算属性，分母0时nil。

当前只有一个摘要，没有筛选枚举、趋势点、统计状态、跨任务聚合或多版本唯一键。`PlanPerformance.id` 目前就是planID，不适合同时出现同一方案多版本／多批次；扩展时向A提出最少字段和唯一键。

本模块可增 `AnalyticsFilterView`、`AnalyticsTrendView`、`AnalyticsComparisonView`、`AnalyticsMetricDetailView`、`AnalyticsScopeHeader`、`AnalyticsSelection` 等。筛选／图表指标属于模块局部状态；Shared统计对象／fixture／批次来源必须通过A整合。不得编辑A/B/C的业务View或直接生成审批任务。

## 3. 首页布局

按以下顺序：时间预设 → 明确日期范围 → 人群／方案选择摘要 → 统计完成状态／样本说明 → 五项合计指标 → 转化率／派生指标入口 → 统一指标选择与趋势 → 方案对比表 → 任务／版本／归因口径说明。

- 默认为历史近7日、人群01、方案01／02，同组A/B样本。
- 统计中、无匹配、已统计0明确显示，不能都画成0。
- 查看详情有真实导航与返回；筛选应用后摘要、图表和对比同时变化，不只有顶部文字变化。
- 展示一套方案时隐藏第二图例／B列，不虚构第二套线。
- 保持黑白灰；系统日期／金额格式用共享 DemoFormat，图表不引入彩色系列。

## 4. 时间预设与确定口径

支持“近7日”“近30日”“近3个月”，不可把近3个月改名90天或自然季度。

采用统一**Demo约定**：上海时区，以固定参考日2026/10/11为最后一天，包含参考日，内部结束时间为次日00:00（半开区间）；近7日／30日分别从结束时间减7／30日，近3个月从结束时间减3个日历月。

| 预设 | 展示起止日 | 内部区间示意 |
| --- | --- | --- |
| 近7日 | 2026/10/05—2026/10/11 | [10/05 00:00, 10/12 00:00) |
| 近30日 | 2026/09/12—2026/10/11 | [09/12 00:00, 10/12 00:00) |
| 近3个月 | 2026/07/12—2026/10/11 | [07/12 00:00, 10/12 00:00) |

使用带Asia/Shanghai时区的Calendar计算，处理跨月、闰月，不以秒数乘90代替日历月。上述是演示约定，正式是否纳入当日／归属时区仍待产品统一。

两方案始终共用一个范围，没有“A近7日／B近30日”的比较配置。需要比较不同预设时只能整体切换，不给不同范围的结果加同组对比标签。

样本数据必须覆盖三个预设或对无样本组合明确空状态。不能仅把同一周数据改标题为近3个月。共享固定参考日不可被设备当前日期覆盖，否则历史主路径随时间漂移。

## 5. 人群／方案筛选

### 人群

使用编号选择：全部（有对应去重摘要时）、单个人群。第一轮不做复杂多选规则构造；可显示明确的人群范围、版本描述。

全部人群合计需要联合去重fixture，不把8420＋3160当总客户。未提供范围摘要时明确“该范围暂无模拟统计”。

### 方案

支持不指定方案（当前范围合计）、选择一套、选择两套。最多两套比较；重复ID或第三套不得应用。编号是图例和表头的唯一业务名称。

目的／客户阶段不是本轮新增主筛选维度；可在详情作说明，避免把B的列表筛选复制过来。

### 应用／取消

筛选弹页用局部 draft；应用后才更新当前范围，取消保持原结果；清除回到明确默认值。过滤结果使用完整的范围键，不逐块从不同fixture拼出看似完整的页面。

设置对象不可用、历史方案不在最新版列表时：历史仍按ID和版本可读，不默默把它替换为最新方案。没有匹配结果显示空状态，而不是偷偷沿用上次样本。

## 6. 核心指标和派生指标

| 指标 | 单位／计算 | 要求 |
| --- | --- | --- |
| 触达人数 | 人，成功触达去重人数 | 与分配人数、发送次数区分 |
| 成交人数 | 人，同口径去重支付客户 | 不等于订单数 |
| 订单数 | 单，同口径有效支付订单 | 可以大于成交人数 |
| 成交金额 | 元，模型存人民币分 | 对所有展示使用同一格式 |
| 成交转化率 | 成交人数÷触达人数 | 百分数两位小数，分母0为“—” |
| 客单价 | 金额÷订单数 | 订单0为“—”，不是金额÷成交人数 |
| 触达人均成交金额 | 金额÷触达人数 | 人均人民币元，分母0为“—” |
| 每触达客户订单产出 | 订单数÷触达人数 | 单／人，不是限制0—100%的客户转化率 |

这些基本和派生指标必须可查看。首购／复购转化率可以在明细中按有对应分子分母的fixture展示；没有数据时显示“暂无该项样本”，不能用总转化率直接冒充首购率。领券／用券为后续扩展，不做未经数据支持的可点击指标。

保留初始精确样本：

| 指标 | 方案01 | 方案02 | 合计 |
| --- | ---: | ---: | ---: |
| 触达 | 600 | 1,400 | 2,000 |
| 成交 | 36 | 132 | 168 |
| 订单 | 42 | 154 | 196 |
| 金额 | ¥6,300 | ¥23,100 | ¥29,400 |
| 转化率 | 6.00% | 9.43% | 8.40% |

合计转化率是168/2000，不是(6.00%＋9.43%)/2。主样本客单价¥150、触达人均金额¥14.70、订单产出0.098单／人，可作为验证点。所有派生值从当前样本字段算出，不在View硬编码。

## 7. 双方案趋势图

支持触达人数、成交人数、订单数、金额和转化率五种指标切换；图标题、单位、Y轴、tooltip／读数、对比说明同步。

- X轴日期，Y轴只一种单位；金额与百分比不共轴。
- 方案01实线、方案02虚线，图例使用编号，并在辅助功能文字说明线型；不能只靠不同颜色。
- 近7日建议日粒度；近30日可日或周；近3个月可周或月。粒度在页面说明，与fixture时间点一致。
- 趋势点来自 Shared 的 `AnalyticsTrendPoint` 类似轻量类型，不为画图写一套与摘要冲突的模块内随机数据。
- 已统计0点可以画0；未知／统计中点为缺失或显式状态，不用0补齐，也不跨未知段假装连续观测。
- 转化率点必须有当天／该粒度分子分母并独立计算；范围转化率不是每天率的简单平均。
- 每日去重客户可能跨日重复；期间触达合计不能靠趋势点简单相加来推出，使用统一期间摘要。
- 仅一系列／一个点／没有点时布局稳定；无数据使用空状态，不显示虚假的下降趋势。
- 可以点选某日期查看该点读数，或提供同内容的日期明细列表；不要在不可交互图上放看似可用的指标按钮。

## 8. 同组和跨任务比较

### 同组A/B

使用历史批次 `task-history-01` 及方案01/02 V1；展示“同组测试，客户互斥”、人群01、相同区间、各组版本与分配。表格五指标对比及合计准确。

点击方案列／明细入口展示当前方案在这个数据范围的指标和来源快照摘要，不能直接调用B的当前版本详情冒充历史内容。

### 同时间多任务

提供至少一组确定跨任务fixture，展示涉及的批次、范围、方案版本、是否包含多次触达及客户重叠。相同时间但不同人群必须明确范围差异，不说完全可比。

合计客户由预先去重摘要提供。例如演示两个任务的触达2000／1000，重叠300 →联合2700；成交168／90，重叠30 →联合228；假设订单互不重叠196＋100=296，金额29400＋15000=44400元；合计转化率228/2700≈8.44%。这些是**建议新增的Demo样本**，当前代码没有，需A集中加入并写元信息。

订单／金额也必须确认是否重复订单；上述相加仅因fixture明确互斥订单。未知联合范围禁止出一个假合计。“全部”不是简单SUM操作。

不提供显著性检验、自动评选永久最佳方案或因高转化率自动采纳建议。给出“固定样本，需结合样本与条件”的说明即可。

## 9. 版本、批次和可追溯性

所有分析记录按发送当时的人群版本、方案版本、任务／批次关联。方案01更新V2后，历史V1结果仍显示V1。

- 若按编号聚合多个版本，明示“包含V1/V2”，提供批次／版本明细。
- 增补后的性能记录唯一键建议包含批次ID＋方案ID＋版本；不能继续只用planID导致ForEach重复或覆盖。
- 摘要范围、趋势、对比必须来自同一query上下文，不混合不同版本／时间样本。
- 统计页不回写当前方案／人群，不更改任务分组。
- 处理快照查询失败时显示数据缺失，不回退到最新内容。

## 10. 数据状态和新模拟发送

| 状态 | 应显示 | 不允许 |
| --- | --- | --- |
| 完整历史样本 | 完整已知指标／日期／版本 | 伪装成实时真实统计 |
| 新发送统计中 | 已知触达及明确“成交统计中” | 未知成交填0或复制168人 |
| 已统计零成交 | 0成交、0订单／金额，触达非0时0.00% | 与未回流混为一谈 |
| 触达0 | 0触达；转化率“—” | 除零或显示0%下结论 |
| 无匹配数据 | 空状态、原因、恢复样本入口 | 继续展示上一范围的数据 |
| 部分完成／缺失 | 已知字段和缺失标识 | 以默认0补齐全部指标 |

C只提供模拟执行结果、唯一成功触达和批次日期，不提供真实成交。本模块可以有明确“载入本批次模拟统计”演示控制，从Shared挑与人群／方案／分配／版本匹配的场景。没有匹配fixture就继续统计中，不把30/70主样本套到50/50的新任务。

模拟统计控制不得改C的sending／失败状态，未成功发送范围不能被统计成已经触达。加载同一结果两次不能重复累加；重试成功更新同一批次的唯一触达数，不新增重复客户。

C给出的统计业务日使用共同参考日；实际操作留痕时间可不同。筛选使用统计业务日期，并在本地样本说明中明确该口径。成交归因窗口未确定，不硬编码“7天归因”或假装按真实订单支付时间结算。

这是一份可直接交给开发者或编码助手执行的任务提示词。请直接在现有工程里实现功能，不要只返回设计方案。本文定义**下一阶段的完整本地可交互 Demo**；当前仓库仍是只读骨架，不能把本文中的计划类型或页面当成已有实现。
