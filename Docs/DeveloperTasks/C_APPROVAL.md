> 分支建议：`feature/approval`。
> 主目录：`TouchMarketingDemo/Features/Approval`。
> 你负责本次任务调整、人工确认、模拟执行、稍后／拒绝、发送结果和重试，不编辑营销内容或人群规则。

## 你的交付目标

实现稳定可演示的审批闭环：查看待审批 → 调整人群／方案／比例 → 核对版本和资源 → 人工确认 → 保存不可变快照 → 模拟发送 → 查看结果 → 对失败范围重试 → 保留处理记录。

“发送”始终是本地模拟，明确标识，不连接企业微信或店铺。所有下文必交付页面和状态必须能到达；不要求真正发送客户消息，不实现真实客户级去重算法。

## 3. 首页、分组与筛选

顶部只设“待审批”“已发送”两个业务分组，不增加底部 Tab。

- 待审批包含 pending 与 deferred，可按全部／待处理／稍后筛选；deferred 是延后处理，不是自动定时发送。
- 已发送包含已确认任务，内部按 waiting／sending／succeeded／partiallyFailed／failed 筛选；waiting 也属于已发送业务分组。
- rejected 不出现在待审批或已发送主列表，在处理记录中可查看完整被拒任务，不能删掉记录。
- 待审批卡片显示任务编号、来源／测试标记、人群编号、本次预计人数、三个核心画像、两方案的编号／目的／客户阶段、比例／预计人数、操作。
- 8,420 是人群覆盖数，2,000 是本次范围，不混用、不自动全量覆盖。
- 空待审批与筛选无结果区别展示；无任务时不能展示虚假的可点击确认卡片。
- 所有操作实时反映到同一个 session，切 Tab／返回后状态仍正确。

## 4. 调整页面与草稿

打开调整时复制本次任务为局部 draft；未点击保存不更改任务。任务详情可显示草稿预览，但确认必须明确使用哪份已保存配置。

### 可调整

目标人群、一个或两个方案及版本、A/B 分配、恢复 AI 推荐值。不要允许修改人群规则、评分、方案全文、资源本体或人群／方案版本记录。

### 人群选择器

显示编号、覆盖人数、三个核心评分、版本与可用／依据不足状态。选择后使用 Shared 的本场景可触达范围 fixture 更新预计人数，不能直接把人群覆盖数当本次触达数。无范围样本标“待核对”，不得编造可发送人数。

0覆盖／不可用对象不能确认发送；评分依据不足本身不是0覆盖，也不意味着绝对不能触达，应区分该原因并让用户核对。列表缺少引用对象时提示不可用，禁止崩溃或默默选另一个人群。

### 方案选择器

显示编号、目的、适用客户与版本，可查看本模块只读摘要，资源状态可见。选择器不能直接实例化 B 的 DetailView 或在此编辑话术。

同一方案不得在A/B槽位重复；最多两套。单方案添加第二套时给50/50演示初始值并允许调整；删除一套恢复保留方案100%。仅剩一套时不能删到无方案再点击发送。

### 保存与取消

保存有效草稿后更新任务并记录更换人群／方案和分配前后值；没有变化不写重复记录。取消草稿保持原对象／版本／人数。已确认或被拒任务禁止重新进入可写调整流程。

## 5. A/B 交互、输入与人数

1. 初始 A30%／B70%，预计600／1,400。
2. 滑杆、步进和整数百分比输入操作同一份 draft，不使用三套不同状态。
3. 建议只有A是主编辑值，B由100−A生成；若允许两个输入，编辑任一都更新另一组。正在输入的空串／非法值是草稿错误，不能立刻造一个合法任务假装输入成功。
4. 双组A和B均1...99；0／100明确提示改成单方案，不能保存伪双组测试。
5. 非数字、负数、超过100、同方案、总和不为100、第三套方案都不能提交；使用 ABAllocation failable initializer，不能 force unwrap 用户输入。
6. 预计人数统一 `expectedCounts`：A向下取整、B取余。改50/50后2,000→1,000／1,000，不会合计丢人。
7. 小样本导致某组0人时，本 Demo 阻止双组确认，提示调整／转单组。正式小样本规则待细化。
8. 推荐比例另存不可变原值，操作“恢复推荐”回到30/70，不用当前修改值覆盖原推荐。
9. 明确每客户只收一套方案、去重先于分组；用固定预计人数说明，不假装真的持有或计算客户名单。

## 6. 版本变化和资源有效性

确认前比对任务引用版本与当前共享实体版本。

- 人群／方案更新时提示旧版本与当前版本，显示变化摘要，不自动升级任务。
- Demo 提供“继续原版本”与“更新任务到当前版本并重新核对”。继续原版必须能解析真实保存的历史快照；缺快照则阻止，不能回退到最新内容冒充旧版。
- 更新配置后重新计算样本预计范围、资源引用与分配有效性，需要再次人工确认。
- 资源有效性使用B的统一样本／规则，以固定参考日判断。资源失效必须阻止执行，继续旧版本不是绕过资源失效的方法。
- B维护资源内容，你只提示回方案模块替换／选择可用版本；不在审批页新增店铺资源。
- 已发送任务永远显示发送当时快照，而不是最新方案全文。

## 7. 稍后和拒绝

### 稍后

点击后本地确认（可用简短弹窗）→ status为deferred →仍在待审批 →写“操作前后状态、时间、演示运营人员”记录。再次处理可进入调整／确认，不产生发送执行。

### 拒绝

确认页显示任务摘要及可选原因，原因不必填作为 Demo 约定。确认后status为rejected，从待审批移除，处理记录仍可查；取消无变化。不会创建发送批次，不可把拒绝直接改成成功。

不提供未经确认的“撤销已确认发送”或自动重开被拒任务。要重新演示使用统一重置或生成另一条新任务。

## 8. 人工确认与快照

确认页展示：人群编号／版本、预计触达、方案编号／版本／目的／客户、比例／预计人数、资源摘要／有效性、版本核对结果及“本地模拟发送”说明。

- 首次点击“确认发送”进入最终核对；最终按钮明确“确认并模拟发送”。未点击最终确认不更改任务状态。
- 最终提交前再校验，避免核对过程中另一模块编辑导致过期配置。
- 创建一次不可变 `DeliverySnapshot`／执行批次：人群内容和版本、各方案内容和版本、资源必要信息、原分组及数量、去重范围说明、确认时间、任务来源。
- state设confirmed，执行为waiting，再进入sending和预设终态；重复点确认不能创建两批执行、两份快照或重复人数。
- 按ID与当前状态校验保证幂等，不依赖按钮变灰这一层。
- 新批次和历史 `task-history-01` 保持不同 ID。历史固定结果不能被当前任务覆盖。

## 9. 模拟执行和五种状态

为了点击演示稳定，本 Demo 用明确“推进模拟执行／演示结果”入口控制步骤，不使用真实队列、网络、随机失败或持续后台计时器。入口清楚标“演示控制”，不冒充生产操作。

| 状态 | 页面内容／允许操作 |
| --- | --- |
| waiting | 已确认、排队说明、只读快照，可推进模拟开始 |
| sending | 进度／当前模拟范围，不能再次确认或并行重试 |
| succeeded | 成功人数、完成时间、快照、数据入口／状态 |
| partiallyFailed | 成功与失败人数、固定原因、失败范围重试 |
| failed | 失败人数／原因、重试入口 |

至少为五状态提供统一 fixture 或可复现流程。默认主流程可成功；第二样本可部分失败；还要能展示全部失败。可用本模块演示控制选择预设场景，不污染其他模块状态或自动写成交数据。

新任务的统计业务日期采用共享固定参考日，操作留痕可记录实际时间。二者展示含义区分，D按演示业务日期筛选，避免未来克隆时新任务被固定日期范围漏掉。

## 10. 结果与失败重试

结果页：任务编号／状态、原快照、各组分配人数、已成功／未成功、执行时间、失败原因、重试次数、处理记录和数据状态。

Demo 无客户名单，使用明确 aggregate 计数模拟失败范围，不能展示虚构私人联系方式或声称已做真实客户级去重。

### 固定重试样本

2,000人按A600/B1,400分配。部分失败场景A成功450／失败150，B成功1,050／失败350；合计成功1,500、失败500。重试仅处理150／350，若全部补发成功，唯一成功触达为2,000，不能变成3,500。

- 重试确认列出失败范围、沿用方案／版本／分组、资源有效性。
- 点取消不改执行和次数；确认才追加retry记录。
- 沿用原冻结快照，不重新随机分组，不换成最新版；失败资源先提示处理，不能继续发送失效资源。
- 执行中禁重复重试，最终成功后重试入口禁用／消失；累计成功人数不超过原分配人数。
- 本Demo允许“全部补发成功”与“仍部分失败”两种确定结果；次数和剩余失败数均实际变化。
- 不设未经需求确认的正式重试次数上限，不创建生产调度系统。

## 11. 处理记录

提供列表和任务记录详情。记录至少含稳定ID、任务ID、操作类型、时间、前后状态／配置、简短说明和固定演示操作者；无登录权限系统。

需覆盖更换人群、方案、比例、稍后、拒绝、人工确认、模拟开始、模拟结束、重试。初始样本和本次操作均可查。排序按时间／序号稳定，重复操作不生成无意义记录；拒绝任务能从此查看原配置。

## 12. 与 B／D 的共享接口

向A提出并集中合入：任务来源／推荐比例、操作记录、确认快照、执行批次、各组成功／失败计数、重试记录、明确统计状态。当前这些都不存在，字段名称以合入后的 DATA_MODELS 为准。

- B配置规则后调用你提供的共享“由规则配置生成pending任务”入口，保存规则来源、生成周期键并保证不重复；B不执行发送。
- A新建／编辑人群与B方案能被选择器实时读取，旧引用保持原版本。
- 你向D提供批次ID、任务ID、人群／方案版本、业务日期、分配和去重成功触达计数。
- **发送成功不等于成交已经发生。** 新批次成交数据默认“统计中”，不能照抄历史168人／196单／29,400元。D负责选择对应本地结果样本，并标明“载入模拟统计”；没有匹配样本则显示未知。
- 重试更新同一批次的触达计数，D按批次／组唯一键读取，不当作额外新客户。
- 查看数据可调用A维护的ID路由；若首轮没有跨Tab路由，明确指引数据Tab并可筛选对应批次，不能直接实例化 AnalyticsHomeView。
