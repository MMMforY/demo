# 开发者 A · 人群模块完整开发任务

> 分支建议：`feature/audience`。你负责人群业务，并兼任共享基础和最终集成的维护者。此职责不意味着实现其他三人的业务页面。
> 主目录：`TouchMarketingDemo/Features/Audience`。
> 阅读顺序：本文 → 完整产品说明 → 共享协作文件 → 当前源代码。

## 你的交付目标

把当前人群首页／详情占位升级为可完整点击的本地人群管理模块：浏览与筛选、展开六项画像、详情、创建／编辑规则、自定义字段、模拟识别状态、历史版本、人群 AI 建议及采纳。运营可以修改规则、查看新版本，再在审批模块看到对应版本变化。

请实现下文所有必交付功能。分阶段只是为了保持可构建，不表示后面的页面可以省略。正式 AI、客户名单和真实识别算法均不在范围内。

## 1. 文件边界与现状

当前已有：`AudienceHomeView.swift`、`AudienceDetailView.swift`，接收统一 `MockDataStore`。首页读取两个人群和前三项评分，详情显示五项评分与品类、关联方案。当前没有表单、规则类型、历史快照、AI 建议或可变状态。

## 2. 共享接线阶段：必须先完成的小任务

你是四人中明确的共享整合负责人，不需要等待第五名开发者。

1. 建立 `Shared/State/DemoSession.swift`，一个轻量 `@Observable` 引用容器，保存已提交人群、方案、任务和必要的版本／样本结果。以 `MockDataStore.demo` 初始化，App 根创建唯一实例。保持原来的 MockDataStore 为统一 seed，不变成四份模块 fixture。
2. 保留当前核心模型名称和稳定 ID；不可变结构可以通过替换数组元素更新，不必把所有属性改成 var。确定 `saveAudience`、`savePlan`、任务处理和版本查询的最少调用方式，写入 COLLABORATION，不提前设计泛型仓库／事件总线。
3. 在根注入会话，协调四首页读取方式和 Preview 的注入。初期保留 `init(store:)` 作 seed 兼容；不能让某个分支因缺少 environment 实例在启动时崩溃。
4. 建立最小 Shared 版本记录和类型化内容快照，人群／方案记录共用元信息。`VersionRecord` 目前只有文档约定，没有 Swift 实现；请不要假设存在。
5. 接收 B 的资源与触达规则字段清单、C 的任务快照／操作／执行结果字段清单、D 的统计样本／趋势字段清单。由领域负责人提出定义，你统一放入 Shared，按独立文件合入，避免四人同时改一个模型文件。
6. 为建议统一约定 ID、目标对象／基础版本、处理状态、差异／依据；页面分属 A 和 B。无需共享复杂建议 View，通用展示可在第二个真实复用需求出现后提取。
7. 确定共享固定演示参考日为上海时区 2026/10/11。fixture、日期筛选、资源有效期与规则预览以同一参考日解释；操作记录可以用实际操作时间，但不能让固定历史样本因当天变化失效。
8. 提供一个统一、可复现的重置方法。由你在根级放小型“重置演示”入口（如工具栏菜单），保留四 Tab 顺序；各模块不得各自重置不同数据。重置前本地确认，清空当前会话改动并恢复 seed，不引入持久化。
9. 基础变更单独构建并优先合入 `main`，通知 B/C/D 同步。其他人可同时做页面布局和草稿，不要求他们等待你实现整个人群模块。

上述是下一阶段实施要求，本次准备仓库时并未创建 DemoSession。每次增加 Shared 类型，同步 DATA_MODELS；增加 UI token，同步 UI_GUIDELINES；当前实现与计划要分栏记录。

## 4. 人群首页详细要求

1. 显示“人群”、简短说明、人群数量和所选范围去重覆盖人数摘要。
2. 来源筛选：全部、AI 创建、手动创建。切换后数量与列表一致，清空筛选恢复初始样本。
3. 卡片默认仅编号、覆盖人数和三个核心评分：消费水平、购买频次、价格敏感度。评分数值和“低／偏低／中／偏高／高”一致。
4. “展开完整画像”独立于“查看详情”：展开补新品偏好、经典款偏好、主要品类；点击折叠不触发导航。展开状态按稳定 ID 保存，筛选／排序不串到另一个对象。
5. 提供新建与人群 AI 建议入口，均进入实际页面，不放空动作按钮。
6. 明确客户可交叉归属，发送按优先级去重。覆盖总人数不能直接相加。
7. Demo 去重人数由 Shared fixture 中明确的范围摘要提供。例如两个人群 8,420 与 3,160，若为演示增加重叠 580 人，则两者联合覆盖为 11,000；该补充值不是当前已有字段，必须记录为新增样本。没有联合数据的选择显示“待统计”，不编造总数。
8. 无人群与无筛选结果分别展示空状态；后者提供清除筛选，前者提供新建。

## 5. 详情、六项画像和评分说明

详情内容依次组织：编号／覆盖人数／来源／Vn → 五项评分 → 主要品类 → 人群规则摘要 → 建议 → 关联方案 → 更新时间／历史 → 编辑。

- 五项评分独立显示，1—5 格条可以使用黑灰矩形或系统进度表示，但必须同时显示数值与解释。
- 分值缺失用 nil／明确识别状态展示“依据不足”或“待识别”，不是 0/5、不是 1/5。
- 消费水平不解释为个人财富；频次不等同于购买意愿；价格敏感度高不代表“更优”。
- 主要品类采用标签＋占比，人群 01 为 A 60%、B 30%、其他 10%。全模块 Demo 暂按购买件数口径，说明正式分母待细化。
- 评分说明展示维度含义、观察周期、量表版本及更新时间。新增这些字段用 Shared 元信息／快照，不能页面临时写成另一套算法。
- 关联方案反向查询 `MarketingPlan.audienceIDs`。在本模块只读展示编号、目的、客户；需要打开 B 的业务页时使用 A 统一接线的 ID 路由，未接线时明确指引到方案 Tab。
- 无关联方案有独立说明，不误显示空串。

## 6. 创建和编辑人群规则

### 表单内容

创建不要求运营输入人群业务名称，保存后统一发放编号。编辑显示原编号及当前版本，不允许直接编辑稳定 ID、编号或五项画像评分。

最小规则编辑器应支持：字段／维度选择、判断方式、属性值、条件行增删、AND／OR 条件关系，以及给模拟 AI 的规则说明。当前无需嵌套无限逻辑树。

Demo 建议实现的字段：最近购买日期或距离上次购买天数、观察期购买次数、实付金额区间、品类、自定义分类／数值字段。不要引入客户个人信息列表。

### 校验和保存

- 至少一条有效条件；字段类型与操作符匹配，数字可解析、范围下限不大于上限、分类值不得为空。
- 数值和日期类型使用适配的输入，不把所有字段都当自由字符串。
- 同名／同 ID 条件冲突给出可读提示，不默默忽略。
- 无变化保存可以直接返回并说明无修改，不额外制造 V2。
- 新建生成稳定的新 ID／编号及 V1；编辑沿用 ID／编号，V1 → V2，保留旧快照。
- 草稿在点保存前不写到共享实体；取消或返回丢弃草稿。已有修改时提示保留编辑或放弃，不提示“已保存”却什么也没改。
- 保存后出现模拟识别状态及预计覆盖说明，明确固定样本未执行真实客户筛选。
- 初次创建可以没有可用画像；完成模拟识别后才显示选定样本的画像，不能把新增规则映射成未经解释的真实评分。

### Demo 识别约定

使用统一 fixture 的场景（识别中／完成／依据不足／覆盖为 0）。可提供明确的“完成模拟识别”或演示工具选择状态，让演示稳定，不依赖随机数、网络、后台任务或长计时器。保存规则产生一个版本；同一版本的模拟画像完成不重复产生无意义的新版本。规则变更和画像统计刷新分开记录。

## 7. 自定义字段

字段列表包含名称、类型、说明、可选属性值、识别依据、启用状态及版本。实现新增与编辑，并让新字段能在规则编辑器里选择。

- 最小字段类型：分类、数值、日期、布尔；分类可以新增／删除属性值。
- 内置五项画像维度的语义不可改成另一种含义；自定义字段具有自己的稳定 ID。
- 同一字典内名称重复给出提示；去除首尾空白；有效分类值不能为空且不重复。
- 保存字段修改后新草稿使用新定义；历史人群版本保留当时的字段定义，不因字典更新悄悄改变。
- 字段被现有规则引用时，本 Demo 用停用替代删除；停用后不得作为新条件选项，历史仍能显示。这是 Demo 安全约定，不宣称正式产品删除规则已确认。
- 不引入 AI 字段解析服务，字段说明只进入共享样本与展示。

## 8. 历史版本

版本列表按版本降序，显示 Vn、保存／采纳时间、来源、变化摘要。点击查看当时规则、五项评分、品类和相关量表元信息。

初始人群 V1 也应有可读快照。编辑至少产生 V2；历史 V1 必须保持原值。返回最新版仍显示 V2。同一操作重复点击不能产生两个版本。

本轮提供查看与比较变化，不实现一键恢复历史（产品尚未确认）。历史详情中的原 ID／编号保持不变。

## 9. 人群 AI 建议

列表只展示 target 为人群的建议；详情显示对象编号、基础版本、当前规则／建议规则差异、数据范围、原因和预计影响，明确“本地模拟建议”。

- 采纳前不修改人群；点采纳 → 确认提示 → 保存建议变更 → 生成新版本 → 标记已采纳 → 查看结果。
- 取消确认无变化；暂不采纳保留原人群和建议记录，采用该状态为 Demo 展示约定。
- 已采纳建议不能重复采纳，保留生成版本号与记录时间。
- 基础版本与当前版本不一致时提示“建议基于旧版本”，本 Demo 阻止直接采纳，并提示重新核对；不静默覆盖用户的最新编辑。
- 至少提供一条可采纳和一条失效／旧版本样本，统一放 Shared。
- 不实现真实 AI 生成或依据客户秘密数据计算；建议内容只来自固定场景。

## 执行方式与共同限制

这是一份可直接交给开发者或编码助手执行的任务提示词。请直接在现有工程里实现功能，不要只返回设计方案。本文定义**下一阶段的完整本地可交互 Demo**；当前仓库仍是只读骨架，不能把本文中的计划类型或页面当成已有实现。

1. 先完整阅读仓库 `Docs/PRODUCT_SPEC.md`，再读 `README.md`、`Docs/ARCHITECTURE.md`、`Docs/COLLABORATION.md`、`Docs/DATA_MODELS.md`、`Docs/UI_GUIDELINES.md`、`Docs/DEMO_SCOPE.md` 与本文件。
2. 保留现有 Xcode 工程、Tab 顺序、独立 NavigationStack 和共享样式。使用 Swift、SwiftUI、iOS 17+、iPhone 竖屏。仅 Apple 系统框架；Charts／Observation 可以使用。
3. 所有业务数据来自 Shared 中统一 fixture／会话。禁止网络请求、数据库、真实 AI、企业微信、店铺接入、远端图片、外部商品页面、登录权限、第三方包和额外工程工具。
