# 开发者 B · 方案模块完整开发任务

> 分支建议：`feature/plan`。
> 主目录：`TouchMarketingDemo/Features/Plan`。
> 你负责营销内容、店铺资源选择、生日／回访规则，以及方案版本和方案 AI 建议。

## 你的交付目标

将现有两套方案占位升级为可点击的方案管理闭环：查找 → 查看 → 新建／编辑 → 选择资源和关联人群 → 保存版本 → 查看历史 → 配置生日／回访规则 → 生成模拟待审批任务 → 查看和采纳方案建议。

请完成下列全部业务页面与动作。实际营销发送交给 C；人群规则编辑交给 A；图表和指标计算交给 D。App 内只选择店铺既有资源，不创建店铺资源，不打开真实商品网页。

## 1. 文件边界和基线

已有 `PlanHomeView.swift`、`PlanDetailView.swift`，首页每条仅编号、目的、适用客户。当前 `MarketingPlan` 有 `message`、`resourceSummary`、`source`、`audienceIDs` 与 `version`，还没有资源对象、规则、时间记录、版本快照或可变会话。

模块专属表单和组件可增于本目录，例如 `PlanEditView`、`PlanResourcePickerView`、`PlanRuleListView`、`PlanBirthdayRuleView`、`PlanFollowUpRuleView`、`PlanVersionDetailView`、`PlanSuggestionListView`。创建与编辑可以复用同一表单；全量／定制化话术使用统一方案模型，不另造第二套方案列表。

共享资源、触达规则、历史／建议类型及 fixture 需要进入 Shared，先提出最小字段清单，由 A 集中合入。你不得直接修改人群、审批、数据 View 或独自修改根 Tab。

## 3. 首页与筛选

1. 标题“方案”；显示筛选后方案数量；新建方案入口；触达规则入口。
2. 编号搜索支持“01”“方案 01”和去除首尾空格的输入。按编号查询，不引入网络或模糊 AI 搜索。
3. 目的筛选使用共享 `PlanPurpose` 六值：新客培育、首购转化、复购促进、价值提升、关系维护、流失召回。
4. 客户阶段筛选使用共享 `CustomerStage` 七值：新建立联系、未首购、已购、持续复购、低活跃、长期未购、不限。
5. 搜索／目的／阶段按 AND 组合，清空恢复全部；无结果时给出清除筛选按钮。筛选项本身不等于单条方案内容。
6. 每条方案严格只有：编号、目的、适用客户，加必要的导航箭头。不要额外放话术、版本、更新时间、生日／回访标签、资源和来源。
7. 用途相同的方案 01／02 是合法数据，不合并、不隐藏、不重新命名。
8. 点击进入独立详情页；新建后列表增加新编号，排序变化不改变旧编号。

## 4. 详情信息与只读关系

显示编号、Vn、目的、客户阶段、完整话术、资源详情、关联人群编号、创建来源、创建／更新时间、建议采纳状态、历史与编辑入口。

- 话术可多行，长内容在小屏可完整滚动阅读，不用固定高度裁切。
- 关联人群来源为 `audienceIDs`，通过 shared session 按 ID 取编号。未知／不可用人群显式说明。
- 人群摘要可显示宏观画像，但不能在方案详情直接编辑人群规则，不能引用 A 的具体 DetailView。
- 资源从 ID 解析，不仅维护一份容易过时的 `resourceSummary` 字符串；老字段可保留为展示兼容，由 A 统一迁移。
- 初始方案 01 是复购促进／已购，内容为关怀与回购礼遇、优惠券；02 为另一话术、商品推荐。保留既有两方案 ID。
- 资源无效有状态文字和“编辑替换”入口；历史版本仍显示当时资源快照，不把旧记录重新标记为最新内容。

## 5. 新建、编辑与保存

### 输入项

选择一个主要目的、一个适用客户阶段；填写非空话术；选择已有资源；关联零个或多个人群。编号自动生成，不让运营输入任意业务名称替代编号。

新建可以选择“手动创建”或“采用模拟 AI 模板”。模拟 AI 模板从 Shared 中读取，填入草稿后仍需用户核对保存；不调用真实服务。编辑既有方案保留原始创建来源，用版本变更来源记录手动编辑。

### 草稿行为

- 打开编辑时复制内容为局部草稿，修改不立刻影响列表／审批任务。
- 取消、返回和放弃修改保持旧内容；有未保存修改时提示继续编辑或放弃。
- 目的／客户不能空；话术去空白后不能为空；资源有效、关联 ID 存在。
- 输入错误显示具体字段，不仅显示通用“失败”；不能用断言处理用户输入。
- 新建生成稳定 ID／新编号及 V1；保存已有内容生成 Vn+1，并写内容快照和变更说明。
- 无实质变化不创建多余版本；连点保存不重复新增同一对象／版本。
- 保存后详情和首页立即更新，切 Tab 仍可查到；原审批任务的引用版本不被静默升级。

### 资源组合 Demo 约定

产品尚未确定多资源组合上限。本阶段采用**零或一个主资源**（券／抽奖／商品三选一），表单可不带资源；不得因没有资源阻止合法纯话术方案。这个约定在交付文档标为 Demo 简化，未来允许组合时再扩展，不宣称为正式业务规则。

## 6. 本地资源选择器

由 Shared 提供静态资源表，至少包含可用优惠券、可用商品、可用抽奖和一条失效资源。只有样本资源，不访问店铺。

| 类型 | 最小展示信息 |
| --- | --- |
| 优惠券 | ID、名称、面额、使用门槛、有效起止日、可用状态 |
| 抽奖 | ID、活动名称、活动说明、有效期、可用状态 |
| 商品 | ID、商品名称、价格、品类、可售状态、演示链接说明 |

- 资源类型分段切换，当前选择明确勾选，确定后返回方案草稿；取消保持旧选择。
- 失效资源仍可查看原因但不能新选；已绑定的失效资源给出替换入口。
- 有效期以共同固定参考日 2026/10/11 判断，避免演示日期漂移。
- 商品可以存示例 URL 字符串作快照，但不能使用 Link、openURL、WebView、远端图片加载等真正发请求的能力。展示“演示链接，未访问店铺”。
- 不提供创建优惠券、修改商品、配置奖品按钮。
- 更换资源只修改草稿，点击保存才影响当前方案版本。
- 与 C 共享同一资源有效性判断，不能 B 显示有效、C 却独自判无效。

## 7. 历史版本与方案 AI 建议

### 历史

版本列表：版本号、更新时间、变更来源、摘要。详情展示当时目的、客户、话术、资源引用／必要资源信息快照及关联人群 ID。至少有初始 V1 和编辑后 V2 可比较。

不实现一键恢复历史；查看历史不能改变当前版本。历史已发送任务继续引用其方案版本，不用新的话术覆盖。

### AI 建议

只读取目标为方案的建议。详情显示基础版本、当前话术／资源与建议差异、参考数据时间与原因、预计影响。明确“本地模拟建议”，不把单次转化率高当永久最优。

- 查看建议不修改方案。
- 采纳需要确认，确认后生成一个新版本并记录建议已采纳；取消无变化。
- 暂不采纳保留旧方案与记录，这一额外状态按 Demo 约定处理。
- 已采纳不能重复生成版本；基础版本不匹配时阻止直接覆盖当前编辑。
- 若建议引用失效资源，采纳前要替换或提示不可采纳，不因是 AI 建议而放宽资源校验。
- 采纳结果页显示编号、新版本、变更摘要和返回详情入口；完整数据来自共享会话，不靠独立页面布尔值伪造状态。

## 8. 触达规则列表与共同行为

触达规则与营销方案是不同对象。规则定义何时／哪些条件生成待审批，方案定义发送内容。一个方案可被多个规则使用，修改规则不直接修改方案。

列表显示生日／回访类型、启用状态、周期或条件摘要、方案编号、单／双方案分配、卡片生成时间、最近生成记录。可以新建／编辑规则、开关启用状态、预览本次模拟范围。

- 保存规则仅保存配置，不自动发送，不能启动后台通知、后台调度或网络任务。
- 设置启用不立即生成无限任务；通过明确的“预览并生成模拟待审批”按钮演示规则到期。
- 点击预览先展示参考日、满足条件的预设范围、去重后的预计人数和方案版本。点击确认生成后，调用共享入口新增 pending 任务；取消不新增。
- 同一规则＋同一演示周期不能重复生成两条任务。提供明确“本周期已生成”说明；生成时间与状态记录可查看。
- 规则不存在满足客户／预计人数 0 时只展示无匹配结果，不产生可发送空任务。
- C 负责审批任务结构和处理；你通过共享入口生成任务，不复制 Approval View 或自己执行发送。

## 9. 生日规则表单

包括：启用状态、生日条件（Demo 默认为参考日当天生日）、卡片生成时间（时分）、方案选择（一到两套）、默认比例及 AI 推荐比例样本。

- 生日信息明确来自本地样本假设，不说企业微信基础资料一定包含生日。
- 单方案 100%；双方案不同 ID、各1...99且和100。使用同一 ABAllocation 校验。
- 日期异常如 2/29 不实现复杂全年调度；若增加该样本应明确固定演示映射规则，不擅自规定正式产品闰年算法。
- 保存和取消行为与方案表单一致，不能保存无方案或同方案双组。
- 保存后通过预览演示生成待审批，任务 source 明确是生日规则，审批页能看到。

## 10. 定期回访规则表单

包括：启用状态、回访周期（三个月／六个月）、起算依据、卡片生成时间、满足条件的范围摘要、方案选择和比例。

正式起算口径待细化。本 Demo 默认“最近一次购买”作为起算依据，并在界面说明及交付文档标为演示约定；不默默混用最近回访时间。采用日历月加减，不把三个月无条件写成90天。

- 改周期后预览显示明确参考日期、样本规则和预设覆盖人数；数字不是从真实订单计算。
- 同样支持单／双方案、默认与恢复推荐比例。
- 自动生成卡片只作本地显式模拟，规则到期永远不绕过 C 的人工确认。
- 规则改动不会改写已经生成任务的方案版本／分配；生成时保存配置来源摘要。

## 11. 共享数据提案与对接

向 A 提交最小 Shared 增补：`StoreResource`、`ResourceKind`、`TouchRule`、`TouchRuleKind`、方案创建／更新时间、资源 ID 引用、规则生成记录，以及方案建议／版本内容快照。这些是计划名字，不是当前现成类型；A 确认后统一命名。

| 对接人 | 提供／消费 |
| --- | --- |
| A | 消费最新人群与快照；提供方案 audienceIDs 和资源／规则类型；A 整合共享会话与公共元信息 |
| C | 提供可选方案、版本内容、资源有效性、规则来源与生成配置；消费统一新增待审批入口 |
| D | 提供编号／目的／版本描述；不直接写营销指标或更改历史统计 |

需要生成待审批时，由 C 提出并实现共享任务构造／记录操作，由 A 整合入口；B 只传规则配置和预览范围。此依赖未合入前可以完成表单和只读预览，但最终验收必须验证审批 Tab 的实际新增任务，不能停留在成功弹窗。

## 12. 建议实施顺序

1. 查看基线与提最小 Shared 需求；先做列表、筛选和详情。
2. 共享 session 接入后做草稿、创建／编辑、保存及取消。
3. 资源选择与有效性、版本快照。
4. 生日／回访配置与待审批预览，和 C 接任务生成。
5. AI 模拟模板、建议采纳、历史和失效状态。
6. 与 A/C/D 集成、自查并整理交付文档。

## 执行方式与共同限制

这是一份可直接交给开发者或编码助手执行的任务提示词。请直接在现有工程里实现功能，不要只返回设计方案。本文定义**下一阶段的完整本地可交互 Demo**；当前仓库仍是只读骨架，不能把本文中的计划类型或页面当成已有实现。

1. 先完整阅读仓库 `Docs/PRODUCT_SPEC.md`，再读 `README.md`、`Docs/ARCHITECTURE.md`、`Docs/COLLABORATION.md`、`Docs/DATA_MODELS.md`、`Docs/UI_GUIDELINES.md`、`Docs/DEMO_SCOPE.md` 与本文件。
2. 保留现有 Xcode 工程、Tab 顺序、独立 NavigationStack 和共享样式。使用 Swift、SwiftUI、iOS 17+、iPhone 竖屏。仅 Apple 系统框架；Charts／Observation 可以使用。
3. 所有业务数据来自 Shared 中统一 fixture／会话。禁止网络请求、数据库、真实 AI、企业微信、店铺接入、远端图片、外部商品页面、登录权限、第三方包和额外工程工具。
4. 真实后端能力用确定的本地样本与明确“模拟”标识展示；不要随机生成结果，不伪造真实计算、营销归因或真实发送。
